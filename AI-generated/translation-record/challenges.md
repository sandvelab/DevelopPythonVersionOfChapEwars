### CH-07

INLA error: `Locations are too close for f(ID_time_cyclic, model="rw1", ...): min(diff(sort(x)))/diff(range(x)) = 8.074e-17 < 1e-06`, on the first predict of the first split. The workspace chapkit kept (`results/diagnose_monthly/failed_predict_workspace/`) shows historic.csv with integer months and future.csv with `month` = 10.00000000000001, 10.999999999999986, 12.000000000000018: chap's default `climatology` provider regresses every non-target column on month of year for the forecast window. predict.R only derives `month` from time_period when no `month` column exists. The same file reduced to the six contract columns runs (`outcomes.txt`). The weekly Nicaragua file carries only contract columns and ran unchanged. Not an anchor failure: the model runs through chap on data shaped as its README specifies.

Raised 2026-10-14, batch 2.

### CH-08

ModelConfiguration.additional_continuous_covariates defaults to [], and `_chapkit_config_payload` always sends it; the service treats [] as 'no covariates', not as its default list. Nothing warns. Found by reading chap_core/models/external_chapkit_model.py before the first run, so no run was affected; it matters for the batch-4 config variants and for any reader of the tutorial.

Raised 2026-10-14, batch 2.
