# Plans for AI generation

Plans executed by `/do`. Planning happens while I am present to answer questions, so that
execution — possibly days later, in a session with none of the planning conversation in
context — does not stall on something one sentence would have settled.

The test for a finished plan: **could a session with no memory of the planning conversation
run it end to end without asking anything?**

- Start from `plan-template.md`. Name plans `YY-MM-DD_camelCaseName.md`.
- A plan is edited as it runs: its batch ledger (§6) fills in, sketched phases become
  concrete batches, and decisions settled during execution are appended to §4b with their
  agency. The plan as delivered is archived to `Archive/plan-as-delivered/` before the first
  batch so the drift is measurable.
- A plan accumulates one link per executed batch under *Batch ledger — reports*. Earlier
  outputs are never overwritten.
- Record decisions already taken, so execution does not reopen them.
